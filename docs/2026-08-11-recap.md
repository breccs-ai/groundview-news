# Ground View News — Work Recap

Date: 11 August 2026  
Status: Preview deployed; production deployment intentionally pending verification.

## Completed today

### Writer application protection

- Diagnosed both writer application paths:
  - `/api/writer/apply`
  - `/api/journalist/register`
- Confirmed applications are stored in `profiles` with `subscription_status` values such as `pending_approval`, `active`, and `rejected`.
- Confirmed rejected applications are excluded from the admin Pending Writer Applications queue.
- Added a hidden `website` honeypot to both application forms.
- Added silent server-side honeypot disposal before Auth, database, or email work.
- Added shared server-side content heuristics for names, pen names, and bios.
- Added privacy-preserving rate limiting:
  - Maximum three accepted application attempts per IP hash per rolling 24 hours.
  - Raw IP addresses are not stored.
  - SHA-256 hashes are salted using `WRITER_RATE_LIMIT_SECRET`.
  - Database locking prevents concurrent-request bypasses.
- Added separate secure Vercel secrets for Preview and Production. Different values are acceptable and intentionally isolate their counters.

### Approval and writer access

- Documented the writer approval email and publishing workflow.
- Updated the approval email to explain earnings, payout choices, and the advertising-funded writer pool.
- Corrected an access-control weakness: pending or rejected applicants can no longer use the server article API.
- Article creation and modification now require an authenticated, approved, active writer profile.
- Pending writers no longer see article-submission actions in their dashboard.

### Writer remuneration

- Preserved the existing configurable writer share pool, currently defaulting to 30% of net advertising revenue.
- Added server-only payout profiles supporting:
  - Bank transfer
  - Wise
  - PayPal
  - Mobile money
  - Remittance services
  - Other manually described methods
- Added current-month accruing estimates and per-article contribution estimates.
- Added settled earnings history, available balance, payments in progress, and paid totals.
- Added a configurable payment-request minimum, defaulting to £25.
- Added an atomic available-balance check to prevent duplicate or excessive payment requests.
- Added payment-request status history for writers.
- Added writer and admin notification emails.
- Added an admin remittance queue to the Revenue page.
- Added controlled payment transitions:
  - `requested` → `processing` or `rejected`
  - `processing` → `paid` or `failed`
  - `failed` → `processing` or `rejected`
- Marking a request paid requires a transaction reference.
- Payout instructions are snapshotted when a request is submitted.
- No Stripe Identity or KYC code was changed.

## Important operational notes

- Do not commit `.env.local`, `.vercel`, Vercel secrets, Supabase credentials, or real payout details.
- The Preview and Production rate-limit secrets are intentionally different; no change is required.
- Changing a rate-limit secret temporarily resets that environment's IP counters because new hashes no longer match previous hashes.
- Writer earnings are estimates until the monthly revenue calculation settles them.
- Earnings depend on net advertising revenue and meaningful reader engagement; they are not guaranteed.
- Article sharing and advertiser introductions are optional and do not affect editorial decisions.
